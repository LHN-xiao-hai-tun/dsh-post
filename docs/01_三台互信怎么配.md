# 01 · 三台互信怎么配

目标：**每台机器都能免密 ssh 到另外几台**，而且用的是**别名**。
这一篇只讲 ssh 这一层；投递与聊天室怎么用见 `README.md`。

> 为什么非要别名：`bridge.toml` 里只写别名（`tablet`、`phone`），
> 不写 `user@ip`。这样换 IP、换端口、换密钥只改 `~/.ssh/config` 一处，
> 三台机器上的配置一个字都不用动。

---

## 一、先决定谁连谁

```
电脑 (pc) ──ssh──> 平板 (tablet)
  │                   │
  └────ssh────-> 手机 (phone) <──ssh── 平板
```

本包**不需要**全互联。真正的要求只有两条：

1. **谁要投件，谁就得能 ssh 到收件那台。**（`bridge.post` 是主动推）
2. **聊天室的中心文件在哪台，谁要读写它，谁就得能 ssh 到那台。**
   （`[hub].host` 指的那台）

最常见的简化：**所有人都能 ssh 到电脑**（电脑当中心），
平板和手机之间不必互通。这最省事，也最容易排查。

---

## 二、生成密钥（没有就做一次）

每台机器各自做一次：

```sh
# Linux / macOS / Termux
ssh-keygen -t ed25519 -C "dsh-post@这台机器的名字"
# 一路回车（空密码）。想上口令也行，但那就要 ssh-agent 一直活着。
```

Windows（PowerShell，OpenSSH 客户端自带）：

```powershell
ssh-keygen -t ed25519 -C "dsh-post@pc"
# 默认落在 $env:USERPROFILE\.ssh\id_ed25519
```

---

## 三、把公钥装到对端

同一条命令对每台「你要连过去的机器」做一次：

```sh
# 在电脑上，把公钥装到平板和手机
ssh-copy-id -i ~/.ssh/id_ed25519.pub <平板上的用户名>@<平板地址>
ssh-copy-id -i ~/.ssh/id_ed25519.pub <手机上的用户名>@<手机地址>
```

Windows 上没有 `ssh-copy-id`，用这一段（把变量换成你的）：

```powershell
$key = Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
ssh user@host "mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo '$key' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

> ⚠️ 权限是硬要求：`~/.ssh` 770/700、`authorized_keys` 600。
> 权限松了 sshd 会**静默拒绝**公钥，日志里只有一句 `Authentication refused: bad ownership or modes`，
> 表现出来却是「密钥没生效」，很容易往密钥本身去查。

---

## 四、配 `~/.ssh/config`（关键一步）

在**每一台要往外连的机器**上写：

```
# ~/.ssh/config      ← 示例；192.0.2.x 是 RFC 5737 文档保留段，换成你自己的地址
Host tablet
    HostName 192.0.2.11
    User 你的用户名
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ServerAliveInterval 20
    ServerAliveCountMax 3

Host tablet-lan
    HostName 192.0.2.12
    User 你的用户名
    IdentityFile ~/.ssh/id_ed25519

Host phone
    HostName 192.0.2.13
    User 你的用户名
    IdentityFile ~/.ssh/id_ed25519
```

几个刻意的选择：

| 写法 | 为什么 |
|---|---|
| `IdentitiesOnly yes` | 不然 ssh 会把 agent 里的密钥挨个试一遍，机器一多每次连接就慢几秒 |
| 两个别名指同一台（`tablet` / `tablet-lan`） | `bridge.toml` 的 `aliases` 是**按顺序试**的，主地址不通会自动换下一个 |
| `ServerAliveInterval 20` | 手机/平板休眠后 TCP 会假活，不设这个会卡到超时 |
| 不写 `ControlMaster` | 多路复用省时间，但连接一挂整个通道都挂，排查时更难看清是谁断了 |

Windows 上的路径是 `C:\Users\<你>\.ssh\config`（⛔ 没有 `.ssh` 就自己建一个目录）。
**编码必须是 UTF-8 无 BOM**，用记事本存成「带 BOM 的 UTF-8」会让 ssh 报
`Bad configuration option`。

## 五、验证（这一步不能跳）

```sh
ssh -o BatchMode=yes -o ConnectTimeout=5 tablet -- true && echo "平板 OK"
ssh -o BatchMode=yes -o ConnectTimeout=5 phone  -- true && echo "手机 OK"
```

三个参数各管一件事：

- `BatchMode=yes`：**禁止交互提问**。不加它，主机指纹没确认过时会卡在那里等人敲 `yes`，
  而计划任务里没人可敲 —— 表现就是「每轮都卡住、没日志、也不报错」。
- `ConnectTimeout=5`：不要无限等。
- `-- true`：只跑一个什么都不做的命令。**只读探活**，不碰对方任何文件。

### 第一次连接：先把指纹认掉

`BatchMode=yes` 在第一次连接时会直接失败（不知道该不该信任这台主机）。
所以**先手工连一次**，看清指纹再确认：

```sh
ssh tablet      # 手工连一次，看清指纹，输 yes
exit
```

之后再跑上面的 `BatchMode` 验证。指纹认过之后会记进 `~/.ssh/known_hosts`，之后就不再问。

> ⛔ 别为了省事关掉主机指纹校验（`StrictHostKeyChecking no`）。
> 那等于让「有人在中间转发」这件事变成常态，而你的信里会有工作区路径和正文。

## 六、把别名写进 `bridge.toml`

```toml
[device.tablet]
name = "平板"
workspace = "/srv/work"              # ⚠️ 示例路径，换成你那台的绝对路径
inbox = "收件箱"
outbox = "发件箱"
aliases = ["tablet", "tablet-lan"]   # ← 和上面 Host 名一字不差
```

- `aliases` **按顺序试**，第一个连上的算数。
- 本机那台 `aliases = []` 就行（不需要连自己）。
- 每台机器上的 `bridge.toml` 可以**一模一样**，靠 `[general].me` 区分本机。

---

## 七、查不通的时候按这个顺序

1. `ssh -v -o BatchMode=yes tablet -- true` —— 看卡在哪一步（`-v` 会打出协商过程）。
2. 卡在 `Offering public key` ⇒ 公钥没装上，或 `authorized_keys` 权限不对。
3. 卡在 `Host key verification failed` ⇒ 指纹没认（见上一节）。
4. 卡在 `Connection timed out` ⇒ 网络/防火墙，不是密钥问题。
5. 通了但**只有第一次通** ⇒ 对端 IP 变了，加第二个别名或换静态地址。
6. 计划任务里连不上、命令行里能连 ⇒ 计划任务跑在**另一个用户**下，那个用户没有 `~/.ssh`。

Windows 上还有一个特有现象：**每次调用 ssh 都弹一个黑窗口**。
这不是配置错了，是控制台子系统程序的行为；本包内部调用 `ssh` 时加了
`CREATE_NO_WINDOW` 标志来压住它（见 `bridge/config.py` 的 `_NO_WINDOW`）。
如果你自己写脚本调 ssh，也会遇到同样的窗口。
